# Context State Governance｜上下文状态治理

一个小型、与具体 Memory 后端解耦的 Skill，用于从互相冲突的长上下文、项目记忆和跨会话历史中恢复**经过验证的当前状态**。

## 为什么需要它

长期记忆系统即使“记住更多”，如果混淆以下问题，仍然可能让协作变差：

- 一句话到底来自哪里；
- 当时依赖的前提现在是否仍成立；
- 用户是否真的进行了实质确认；
- 后来的确认是否是在错误问题框架下形成；
- 历史证据现在是否还应该指导执行。

核心思想：

> **记得，不等于知道什么现在仍然有效。**

因此，本 Skill 在 Memory Retrieval 之上增加一层状态治理：

`来源分离 → 前提检查 → 冲突检测 → 人工裁决 → Validated Baseline`

## 核心机制

- **Validated State Wins**：不是“最后一次写入覆盖”。
- **来源分离**：当前会话、项目记忆、历史会话、AI建议和用户确认不能混为一谈。
- **前提失效**：历史上明确确认过的决定，可以失去当前执行权，但不能被抹掉。
- **开放式裁决**：`1A / 1B / 1C / ...` 只是降低注意力成本的协议，不是强制选择题。
- **自然语言高于标签**：允许 `1A/B`、分阶段选择、修改选项、新增选项或完全自然语言回答。
- **三层证据结构**：
  - Validated Baseline：现在怎么做
  - Decision Ledger：为什么
  - Raw Evidence：当时真实发生了什么

## 一个匿名例子

历史记录中存在冲突：

- 早期路线：自己开发某个子系统；
- 后来发现：成熟开源组件已经解决大部分问题；
- 中间曾出现若干“继续”确认，但这些确认发生在旧问题框架仍在主导讨论时。

本 Skill 不会使用“最新确认优先”。

而是将实质冲突压缩为：

**1A** — 继续自研。

**1B** — 只保留独特治理层，基础设施改用成熟组件。

**1C** — 暂停两者，重新检查关键前提。

用户可以回答：

- `1B`
- `1A/B`
- `当前1B，满足X条件后转1A`
- `都不对，我真正的意思是……`

最终以用户完整自然语言意图为准。
